# Decision: 在隔离目录中安装精确的官方 DSH 版本

Status: implemented
Category: architecture

[English](2026-08-15-isolated-exact-dsh-versions.md) | 简体中文

## 问题

用户需要安装、保留、切换和回退官方 DSH 版本，同时不能依赖全局包状态、留下不完整安装，或者让更新静默替换用户选择的版本。

## 决定

每个受管理的 DSH 版本都必须是官方 npm 包 `@deepseek-ai/dsh` 中的精确 SemVer，并使用独立的应用自有目录。安装先在临时目录中完成，验证包和 CLI 入口后再原子发布完整目录。多个完整版本可以并存。除非用户明确要求安装并启动，或者随后主动选择，否则安装不会改变当前选中版本。

## 考虑过的替代方案

**单个可变安装目录。** 原地更新会增加回退难度，并可能在中断后损坏唯一可用安装。

**直接安装移动的 dist-tag。** `latest` 等标签会让安装结果随时间变化，降低可审计性。

**全局 npm 安装。** 这会把行为绑定到系统权限、PATH、Node.js 和其他用户包。

## 影响

应用会占用更多磁盘空间，并需要枚举和清理自己的版本目录。作为交换，安装可复现，中断操作不会覆盖可用版本，用户可以继续主动回退。

## 验证

版本管理测试覆盖精确版本校验、临时目录清理、原子发布行为、卸载所有权和选择行为。安装包 E2E 覆盖最终交付的版本管理路径。
