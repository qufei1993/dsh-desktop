# Decision: DSH 与 Desktop 更新保持独立并由用户控制

Status: implemented
Category: product

[English](2026-08-15-independent-update-channels.md) | 简体中文

## 问题

官方 DSH 包和 Desktop 应用具有不同的发布者、兼容性风险、安装位置和回退行为。把两者视为同一更新流可能静默替换用户选择的 DSH 版本，或者暗示 Desktop 发布能够控制官方 DSH 数据兼容性。

## 决定

官方 DSH 版本只来自官方 npm 包，并且只能通过用户明确操作安装或选择。DSH Desktop 应用更新只来自本仓库 GitHub Releases。发现较新的 DSH 版本时只显示可关闭提醒，不自动安装或切换。macOS Desktop 更新采用检查后手动下载，Windows 可以使用应用内更新器。

## 考虑过的替代方案

**自动安装最新 DSH。** 这会消耗带宽、未经许可改变本地程序状态，并模糊检查和安装之间的区别。

**安装后自动切换。** 这会替换用户当前版本，并可能让官方数据暴露给用户没有选择运行的版本。

**两种产品共用一个更新器。** 这会混淆独立的发布责任、产物、回退单位和兼容性承诺。

## 影响

用户需要做出更多明确选择，也可以继续运行较旧的 DSH 版本。作为交换，更新行为可预测、能够回退，而且任一通道都不会静默改变另一通道。

## 验证

控制器和更新器测试验证只检查行为、明确安装与切换、忽略提醒、macOS 手动交付以及应用更新状态。安装包 E2E 覆盖用户可见的版本管理器。
