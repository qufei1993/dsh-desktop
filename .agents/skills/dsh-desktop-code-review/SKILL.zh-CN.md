# 审阅 DSH Desktop 改动

[English（权威版本）](SKILL.md) | 简体中文（人工审阅）

审阅准确的 diff，并阅读足够的周边代码以理解其行为。形成结论前，阅读根目录 `AGENTS.md`、`.agents/notes/implemented/` 下相关的生效决策以及受影响测试。

优先关注正确性、安全、生命周期清理和被破坏的产品要求，而不是格式。除非自动门禁遗漏的问题会导致语义缺陷，否则不要报告已被门禁处理的样式问题。

## 审阅重点

- 保持官方 DSH 所有权边界：不 patch、不注入、不导入私有 API，也不接管 DSH 配置和用户数据。
- 追踪变更 IPC 的两端。Renderer 输入在主进程验证前都不可信；特权操作必须位于狭窄 IPC channel 后方。
- 检查每个受影响的 `BrowserWindow`：官方 DSH Window 没有 preload；所有窗口保持禁用 Node integration、启用 context isolation 和 sandbox；适用时拒绝权限请求并限制导航。
- 追踪子进程启动、就绪、超时、取消、退出、版本切换和应用关闭。确认每条终止路径的所有权和清理。
- 检查 macOS arm64、macOS x64 和 Windows x64 假设，包括路径分隔符、可执行文件名、进程终止、打包资源和更新器差异。
- 保持精确版本安装、原子发布、可回退性，以及用户控制的 DSH/Desktop 独立更新通道。
- 检查所有应用可见文本是否同时提供简体中文和英文。
- 行为变化需要聚焦回归测试；运行时、打包或边界变化需要覆盖真实交付入口。
- 用户可见行为变化时，检查成对公开文档和 Changelog。
- 质疑超出请求范围的推测性抽象和无关清理。

## 证据和输出

从 `dsh-desktop-pre-push` 选择最窄但充分的检查；没有观察到输出时，不得声称检查已运行。每个缺陷都要给出位置、影响、触发路径和证据。区分阻塞问题和可选改进。没有发现可操作缺陷时，明确说明，并列出仍然存在的测试或平台不确定性。
